# S5: editable-layers on an orthographic canvas, 1M objects behind it

Status: done 2026-11-13 on the workstation (GPU and CPU much stronger than
the reference laptop; accepted risk, decision log section 2). Pass:
editable-layers works on a basemap-free OrthographicView; check-out and
commit round trips are under 100 ms for cells and for 5,000-vertex regions.
Vertex dragging on large polygons drops to about 30 fps here.

## Setup

- Bulk layer: the synthetic 1M cells and 200 regions (S3 Arrow file), one
  SolidPolygonLayer per group, triangles precomputed.
- Sidecar: cells and regions forked from the matching synthetic store
  (`Sidecar.fork_layer`, object ids kept), served by `compass-studio-serve
  --sidecar` through a draft edit API (since replaced by contract v1; see
  "Rerun on contract v1" below).
- Editing: `@deck.gl-community/editable-layers` 9.4.8 (`EditableGeoJsonLayer`,
  `coordinateSystem: CARTESIAN`), deck.gl 9.4.1. Page: `web/src/edit.ts`
  (`bench=edit`), headless Firefox 158, pointer input simulated with
  synthetic PointerEvents on the canvas.
- Hiding a checked-out object in the bulk layer (D8): DataFilterExtension
  with a value filter (`filterSize: 1`, range [-0.5, 0.5]); the filter value
  is an external GPU buffer per sub-layer, and check-out rewrites only the
  object's vertex range (a few hundred bytes), not the whole attribute.
- Per object: pick in the bulk layer, check out, hide, show in ModifyMode,
  drag one vertex over 30 frames, commit `update_geometry`, show the result
  in an overlay layer. One untimed warm-up edit first (layer creation and
  shader compiles cost about 330 ms once).

## Results

| | Cells (8 to 32 vertices), n = 20 | Regions (about 4,950 vertices), n = 5 |
|---|---|---|
| Check-out (request to edit layer rendered) p50 / p95 | 18 / 21 ms | 49 / 66 ms |
| Commit (request to overlay rendered) p50 / p95 | 20 / 22 ms | 40 / 65 ms |
| Frame interval while dragging, p95 | 17.1 ms (60 fps) | 33 to 34 ms (about 30 fps) |
| deck render time while dragging, p95 | 4 ms | 4 ms |
| Vertex ended at the drop point | 20 / 20 | 5 / 5 |

- Draw: DrawPolygonMode with 9 simulated clicks produced one polygon
  (`addFeature`); committing it as a `create` took 32 ms.
- A commit with a stale `base_revision` returned 409.
- On large regions the drag frame time is spent in editable-layers'
  JavaScript (rebuilding the feature and its 5,000 edit handles on every
  pointer move), not in rendering (deck render stays at 4 ms). On a slower
  CPU this will drop further.
- At a zoom that shows a whole region, vertices are 1 to 3 screen px apart,
  so the drag picks a handle 10 to 48 vertices away from the intended one.
  Vertex editing of large polygons needs zooming in (or a tool that edits a
  local stretch of the outline).
- One dragged region became self-intersecting; the server refused it (400,
  "invalid polygon: Self-intersection"). The client needs to validate or
  report this; editable-layers did not prevent it.
- Picking in the bulk layer returned the chosen cell in 13 of 20 cases; the
  others hit an overlapping neighbour (synthetic cells overlap).

## Rerun on contract v1 (2026-11-13)

Same page on the frozen API: layers forked with `POST /layers/{id}/fork`
(cells 9.3 s, regions 0.5 s), check-out with `GET /layers/{id}/features`,
commits with GeoJSON geometry to `POST /stores/{store}/commit`. Cells:
check-out 20 ms, commit 22 ms p95; regions: 52 and 47 ms p95; drag frame
times unchanged. The drawn polygon got id 2^40 (first sidecar-created id),
the self-intersecting region edit returned 422 with the reason, the stale
commit 409.

## Implications

- D8's editing library works on the orthographic canvas; the OpenLayers
  fallback (D5) is not needed.
- Large polygons: 30 fps accepted (owner, 2026-11-13): polygons with many
  vertices are rarely edited by hand. Client-side validity checks before
  commit are still needed.

## Not tested

- That the checked-out object actually disappears from the bulk layer (the
  filter write is in place but was not read back).
- Real mouse input, touch, snapping, holes, multi-polygon edits.
- The reference laptop.
