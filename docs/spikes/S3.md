# S3: annotation scale (5M points, 1M polygons)

Status: done 2026-11-13 on the workstation (decision log section 2: GPU
numbers are optimistic for the reference laptop, an accepted risk). Pass on
frame time, toggles and picking. Memory: 700 MB GPU buffers plus about
0.9 GB of typed arrays, well within the 32 GB machine budget (set
2026-11-13; integrated graphics share that RAM).

## Setup

- Data: `compass-studio-synth` (seed 0): 5,000,000 points; 1,000,000 cell
  polygons (8 to 32 vertices, 20.0M vertices, 18.0M triangles); 200 region
  polygons (500 to 5,000 vertices, 0.57M vertices) on a 200k x 200k px image.
  Arrow IPC files of 72 MB (points) and 383 MB (polygons, with triangles).
- Page: `web/src/annot.ts` (`bench=annot`), deck.gl 9.4.1, served by
  `compass-studio-serve --spike-files`. Headless Firefox 158, 1366 x 682,
  NVIDIA GPU; server limited to 4 CPUs.
- Points: ScatterplotLayer, binary float32 positions, per-point colour,
  DataFilterExtension categories for groups.
- Polygons: SolidPolygonLayer, binary float32 positions, either triangles
  precomputed by earcut (standing in for server-side triangulation, D6) or
  tessellated by deck on the main thread.
- Render time is measured with `gl.finish()` after each frame, so it includes
  GPU work; headless Firefox caps frames at its ~17 ms timer.

## Results (all layers, per-group polygon layers)

| | Precomputed triangles | deck tessellates |
|---|---|---|
| Fetch + parse (points / polygons) | 0.21 / 0.91 s | 0.23 / 0.79 s |
| Build buffers | 0.38 s | 0.21 s |
| First frame (init, upload, tessellation) | 1.6 s | 4.1 s |
| GPU buffer memory | 700 MB | 700 MB |
| Render + GPU sync p95, worst phase (fit view) | 9 ms | 9 ms |
| Frame interval p99 | 17.1 ms | 17.1 ms |
| Group toggle p95 (points / cells / regions) | 18 / 17 / 17 ms | 19 / 18 / 18 ms |
| Layer toggle p95 | 17 to 23 ms | 17 to 23 ms |
| Pick p95 (zoom -2 / 0 / 2) | 10 / 9 / 9 ms | 10 / 9 / 9 ms |
| Correct picks | 300 / 300 | 300 / 300 |

Per layer (precomputed triangles): points alone 95 MB GPU, first frame
0.96 s; cells alone 587 MB, 0.65 s; regions alone 17.5 MB, 0.04 s.

- Toggle and pick times include waiting for the next frame (up to one frame
  interval), so they are user-perceived latencies. All well under 50 ms.
- Precomputing triangles cuts the first frame by 2.5 s and takes the work
  off the browser's main thread: supports D6's server-side triangulation.
- Rendering everything at the fit view (all 6M objects on screen) costs
  about 9 ms on this GPU. The zoomed-out level of detail (D6: centroids or a
  density raster) could not be tuned here: on a weaker GPU the fit view is
  where frame drops will appear first.

## Findings

- **DataFilterExtension categories do not work on binary SolidPolygonLayer
  data in deck.gl 9.4.1**: with all groups enabled the polygons draw nothing
  (picks inside cells return nothing; the same layer without the extension,
  or with `filterSize` only, renders). Per-vertex, per-object and float
  category buffers all fail. Reproduce with `polymode=filter`. Categories do
  work for binary ScatterplotLayer points.
- Workaround used: one SolidPolygonLayer per group (group toggle = sub-layer
  visibility, one colour per group). It also drops the per-vertex colour and
  category buffers: 700 MB instead of 935 MB GPU memory.
- Binary category attributes are used as bit indices directly; deck maps
  categories to bits in order of first appearance, so group ids must be
  rebased to 0..k-1 and listed in order on the first render. Limit: 128
  categories per layer and channel.
- A new `data` object on every `setProps` makes deck re-upload all
  attributes (2.3 s per toggle in a first, faulty harness run): binary data
  objects must stay stable across updates.
- The regions-only run logged 5 render waits that timed out (deck saw
  nothing to redraw); results are unaffected.
